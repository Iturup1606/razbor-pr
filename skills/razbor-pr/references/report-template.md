# Форма разбора

Разделы идут в этом порядке. Пример по этой форме на выдуманном изменении: `example.md`. Размер подгоняй под изменение: маленькое изменение это страница, большое может быть в три раза длиннее, но вода не нужна.

## Содержание

1. Полная форма
2. Короткая форма
3. Как оформить вопрос-паузу
4. Таблица вопросов

## 1. Полная форма

```
# Разбор: (название PR или ветки)

**Что разбираем:** (PR или ветка), основа (хэш), верх (хэш), файлов N, +A / -D строк. Проверки: (зелёные, красные, нет данных).
**Режим:** только чтение, ничего не запускалось и не менялось.

## 1. Зачем это
(2-4 фразы простыми словами. Если описание PR обещает другое, сказать.)

## 2. Карта чтения
(таблица: № | Файл | Менялся | Зачем читать | На что смотреть; под ней фраза про время и список пропущенного)

## 3. Что обещал старый код
(3-5 пунктов: какие свойства работы важны и сохранены ли. Это основа для всех вопросов дальше.)

## 4. Идём по файлам
(по порядку карты. В центре глубже, в периферии одной строкой. Здесь же вопросы-паузы.)

## 5. Вопросы опытного разработчика
(таблица: группа | результат | где проверено)

## 6. Находки
### Исправить обязательно
### По желанию
### Выглядит опасно, но в порядке, и почему
### Сделано хорошо
### Не проверено

## 7. Итог
(одна строка из трёх формул)

## 8. Промт на исправление
(готовый текст или фраза «промт не нужен»)
```

Метки `[проверено по коду]`, `[вывод из кода]`, `[общий опыт]` стоят в конце каждой фразы-утверждения везде, где она есть.

## 2. Короткая форма

Для изменений до 50 строк в одном-двух файлах и для изменений без кода (тексты, зависимости, сгенерированное): разделы 1, 2 (одной строкой), 5 (таблица), 6, 7 и 8. Разделы 3 и 4 только если есть что сказать. В небольшом разборе, где «что обещал старый код» и «идём по файлам» повторяют друг друга, слей их в один раздел. Для зависимостей и сгенерированных файлов вместо глубокого чтения: что поменялось, кто автор новой версии, что делает при установке, не вылезло ли лишнее.

## 3. Как оформить вопрос-паузу

В режиме «целиком» вопрос и ответ разделены линией, ответ не виден до неё:

```
> **Подумайте:** (вопрос на предсказание, на конкретных значениях)

---

**Ответ:** (ответ с метками и местом в коде)
```

В режиме «по шагам» после вопроса остановись, не пиши линию и ответ в том же сообщении. Получив ответ человека, скажи, верно ли, и разбери, где он мог ошибиться.

Хороший вопрос: на конкретных числах, с ответом, который неочевиден и который можно найти по коду. Плохой: «что вы об этом думаете».

## 4. Таблица вопросов

```
| Группа | Результат | Где проверено |
|---|---|---|
| А. Не сломалось ли старое | находка №3 | notify/sms.py:5-13, вызывающие по git grep |
| Б. Сбой и повторный запуск | находка №1 | notify/sms.py:8-12 |
| В. Откат | в порядке | формат данных не менялся |
| Г. Кто и с чем вызывает | в порядке | вход только из внутреннего кода (git grep) |
| Д. Тесты | находка №4 | tests/test_sms.py:14-22 |
```

Результат это «в порядке» (с местом проверки), «находка №N», «не проверено» (с причиной) или «не применимо: причина» (например, откат для правки только текста). Пустых ячеек нет.
